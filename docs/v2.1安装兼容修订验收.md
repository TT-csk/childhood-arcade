# v2.1 安装兼容修订验收（2026-11-27）

版本名仍为 2.1.0，内部版本号 222，包名、签名、游戏目录及11个原生库保持一致。

## 修改

- 优先检查系统可接收的安装入口；API21–23缺少content入口时使用file入口，Android7及以上保留content授权，不使用file URI。
- 将更新APK放在应用更新目录，避免安装前被系统缓存回收；旧电视使用外部应用更新目录，只保留一份待安装APK。
- 下载前预估安装余量，安装前按APK实际原生库大小检查空间。该预估不能替代系统最终检查。
- 校验后保留APK供重试，复用时重新检查大小、哈希、包名、签名及更高内部版本。
- 未完成安装时核对系统返回码与实际已安装版本，避免误称用户主动取消。
- 版本、个人数据和已导入资源检查通过后，清理本轮安装文件。
- 修订后的大厅支持按内部版本号识别未来同名修订；旧2.1仍需手动覆盖一次。

## 验收结果与范围

小米 MiTV4-ANSM0、Android6.0.1、ARM32：用隔离的签名APK夹具触发实际大厅服务，经自动备份、回读及安装包校验后，由HallUpdates自行打开系统安装页（来源显示童年游戏厅）。先返回安装页，验证APK保留及准确提示，再次由同一服务发起更新，复用APK且未访问测试下载地址，系统确认后实际安装至内部版本222。重启大厅后，原存档、收藏、手柄配置逐项比对保留，已导入资源核验通过，安装文件自动清理。

测试工具只提供签名夹具并调用实际服务，随后已移除。本次没有重新从GitHub完整下载新修订包；在线附件替换后的下载及清单哈希仍需回读核验。ARM64已完成构建、签名及静态核验，未在ARM64真机安装。其他品牌、系统版本及低空间边界没有全部覆盖。

## 旧版升级边界

这台电视上原正式2.0的content安装交接实测失败，不能宣传旧2.0大厅独立更新已通过。旧版在目标APK安装前仍执行旧代码，需要手动打开同架构APK完成首次覆盖过渡，不应卸载应用。已装早期2.1（内部版本220）的用户也需手动覆盖同名修订包。资源包继续沿用2.0，无需因更新大厅重新导入。
